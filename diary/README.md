# Development diary

A running record of *why* this project looks the way it does. Each entry is a
markdown discussion of one nontrivial improvement or architecture change: what
prompted it, what approach was chosen, what alternatives were considered and
rejected, and any consequences worth remembering later.

**What belongs here:** decisions that shape the project going forward -
architecture changes, nontrivial improvements, anything a future contributor
(including a future version of whoever's reading this) would otherwise have
to reconstruct from commit messages or guesswork.

**What doesn't:** bugfixes and SPA/tool additions. Those are ordinary,
self-explanatory work - the commit history is the record for them.

## Naming

`YYYY-MM-DD-slug.md`, one entry per file. The date is when the decision was
made/landed, not necessarily when the file was written. The slug is a short,
lowercase, hyphenated description of the topic (e.g.
`2026-09-16-overlay-architecture.md`).

## Format

No fixed template - write it as a discussion, in whatever shape the decision
actually needs. A short entry that's just a paragraph or two is fine; a
longer one with sections is fine too.
